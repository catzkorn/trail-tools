# Go server

The rules here cover all Go code; `services/AGENTS.md` adds the rules for the
Connect services, and `store/AGENTS.md` those for migrations. Format with
`make go-format` (gofumpt), lint with `make go-lint` (staticcheck), and test
with `make test`.

## Packages

- Domain packages (`races`, `plans`, `trips`, ...) hold a `Repository` over
  the database, built with `NewRepository(log, db)`. Its queries are in
  `queries/*.sql`, generated by sqlc into `internal/gen`; `sqlc.yaml` has a
  block per domain.
- Repositories return their own domain types, not sqlc's: convert with
  `xFromDB` and `xToDB` functions. Use `pgtype.UUID` for IDs and `time.Time`
  for times and dates.
- Declare interfaces where they're used, with only the methods the user
  needs, e.g. a service's `RaceRepository`. Producers return concrete types.
- Constructors are `NewX`, taking their dependencies as arguments. `main.go`
  creates and wires everything.
- Use the Go version in `go.mod` and the standard library's newer features:
  range over ints, `min` and `max`, `slices`, `maps`, `cmp.Or`, iterators and
  `sync.WaitGroup.Go`.

## Database

- Queries are lowercase SQL, named `-- name: <Verb><Noun> :one|:many|:exec|:execrows`
  (the names are also the trace span names). Use `returning *` for inserts and
  updates.
- Scope every query of a user's data by the user: `where id = $1 and
  user_id = $2`. That's how access is enforced, so another user's resource is
  simply not found.
- Translate `pgx.ErrNoRows`, and deletes and updates of no rows, to
  `store.ErrNotFound`.
- Convert IDs with `store.StringToUUID` and `store.UUIDToString`, and dates
  with `store.ParseDate`, `store.DateToPG` and `store.DateFromPG`.
- Each round trip costs about 28 ms in production. Don't query in loops; batch
  writes that don't need results with `store.Batch`, which also makes them
  atomic. Only use a transaction for writes that must be atomic or reads that
  must be consistent: begin with `r.db.Begin(ctx)`, `defer
  tx.Rollback(context.Background())`, and run the queries on `r.q.WithTx(tx)`.

## Errors

- Wrap errors with what failed: `fmt.Errorf("failed to get race: %w", err)`.
  Error strings are lowercase.
- Sentinel errors are `var ErrX = errors.New("...")`, or `errX` if
  unexported. Exported ones may reach users through the API, so word them for
  users.
- Report errors that need fixing to Error Reporting with
  `errreport.Reporter.Report(ctx, "Failed to ...", err, attrs...)`, instead of
  logging them. Logs say what happened; Error Reporting says what went wrong.
  When the code carries on without the failed work, say how in the message,
  e.g. "Failed to snap a track to the map, following it with straight legs".
- Don't report errors the user or client caused, like invalid input or an
  expired token. Log those at debug level, or warn for suspicious requests.

## Logging

- Take a `*slog.Logger` named `log`, and use the `...Context` methods with
  typed attributes and snake_case keys: `slog.String("user_id", id)`.
- Messages are capitalized, without a trailing period: "Starting Strava
  sync".
- Log startup and lifecycle events at info, expected client failures at debug,
  and suspicious but handled conditions at warn. Errors go to Error Reporting.

## Outgoing requests

- Never use `http.DefaultClient` or `http.Get`: requests through them are
  reported. Take an `*http.Client` from the caller, created in `main.go` with
  `telemetry.NewClient(timeout)` so its requests are traced, with the timeout
  in a named constant. Libraries that take their client from the context get it
  with `telemetry.WithClient`, and gRPC clients `telemetry.GRPCDialOption()`.
- Create requests with `http.NewRequestWithContext`, and bound calls that
  need it with `context.WithTimeout` and a named constant.
- Use `context.WithoutCancel` to record state that must be saved even if the
  request is canceled.
- The server runs in 512 MiB. Limit the size of what you read into memory
  (`io.LimitReader`), and avoid holding a user's whole history at once.

## Comments

- Doc comments are full sentences starting with the name, on unexported
  declarations as well as exported ones. Packages have a doc comment saying
  what they're for.
- Document constants with their value's reason: "scheduledSyncBudget is how
  long a scheduled sync runs for. It must be less than the request timeout of
  the server."
- Document struct fields' meaning, units, and what their zero or nil value
  means.
- Explain non-obvious code inline: why it's needed and what would break
  without it.

## Tests

- Use the standard library only: `t.Fatalf("CreateRace: %v", err)` for
  unexpected errors, `t.Errorf("got %v, want %v", got, want)` for wrong
  results, and `slices.Equal` or `proto.Equal` to compare. No testify or
  go-cmp.
- Start tests with `t.Parallel()`.
- Write table tests as a slice of structs or a map keyed by the case's name.
- Tests that need a database call `storetest.New(t)`, which creates a
  migrated database for the test, and skips it when `TEST_DATABASE_URL` is
  unset. `storetest.NewUser` creates a user.
- Inject the time with a `nowFn func() time.Time` field rather than calling
  `time.Now` directly where tests need control.
